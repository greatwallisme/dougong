# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

dougong (斗拱) is a Rust implementation of the cordis composition kernel: time composability (every environmental mutation is a revertible effect, undone LIFO) meets spatial composability (declared dependencies resolve reactively as providers come and go). Plugins come in three forms sharing one semantic: in-process Rust (`dougong::Plugin`), dylib/so via C-ABI (trusted code), and wasm components (sandboxed).

`doc/research/` is the semantic source of truth: `cordis.md` (the paper), `study-1..4` (evidence), `dougong-design.md` (decisions D4–D30 plus user rulings R1–R4 and the ABI v3 rulings D-V3-1/3/4/5). When changing behavior that a D-decision governs, update its landing record there.

```sh
cargo build --workspace                                # host build

cargo test --workspace                                 # full suite
cargo test -p dougong --test acceptance                # one test target
cargo test -p dougong provider_identity -- --nocapture # one test by name

# Quality gates - ALL FOUR must pass with zero output / exit 0 before committing:
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps

# End-to-end demos (each must exit 0):
cargo run -p dougong-dylib  --example dylib_demo    # needs: cargo build --workspace (builds greeter-plugin)
cargo run -p dougong-dylib  --example outbound_demo # ABI v3 outbound arms; same dylib artifact
cargo run -p dougong-wasm   --example wasm_demo     # needs the wasm32-wasip2 guest artifact
cargo run -p dougong-loader --example loader_demo   # needs the dylib artifact
cargo run -p dougong-loader --example harness_demo  # multi-plugin composition: needs the dylib artifact + wasip2 guest
cargo run -p dougong        --example health_demo    # health snapshot body composition (host wiring demo)
```

The toolchain is pinned patch-level in `rust-toolchain.toml` (1.99.1) because clippy/rustdoc lints drift between releases. No MSRV is declared or claimed anywhere in the manifests - the pinned toolchain is the only verified one (ruling R4). rustup auto-installs the pinned toolchain and targets on first entry.

## Architecture

Dependency direction: `dougong-abi` (zero-dep C contract) ← `dougong` (kernel) ← `dougong-dylib` / `dougong-wasm` (boundary hosts) ← `dougong-loader` (declarative reconcile). `greeter-plugin` (cdylib) depends only on `dougong-abi`; `greeter-wasm` depends only on `wit-bindgen` + `wit/dougong-plugin.wit`.

Cross-cutting semantics that span files:

- **Fiber driver model (D4)**: each fiber owns one convergence loop (`fiber.rs::drive_loop`). Load order matters: the committed view ω is committed *before* the plugin body runs; a body panic is contained as `fail_load` (body runs on its own task, JoinError becomes failure) — never let a plugin panic kill the driver task.
- **Invariant checkpoints (S1)**: every fiber lifecycle transition (spawn/load/unload/fail/dispose/driver landing) runs the matching `invariant.rs` checkpoint — release keeps O(1) epoch/uid relations, debug adds store/index/registry cross-consistency. A breach panics with a locating snapshot (kernel bug, not a recoverable error). Wire the checkpoint when adding a transition; deep checks must stay dispose-race-tolerant (present ⇒ exact, absent ⇒ tolerated).
- **Cancel scopes (S2)**: every task a fiber owns (listener invocations, the plugin body) spawns through its per-activation `CancelScope` generation (`cancel.rs`); unload and the load rollback reap the scope *before* draining effects, so no spawned guest call outlives teardown, and `dispose` cancels up front so a hung body cannot park the driver forever. Boundary work (bridges, wasm bodies) is tracked-only — never dropped mid-call (a wasmtime store forbids abandoning an in-flight `call_async`), so `Plugin::body_abort_safe` returns false only for wasm. In-process work aborts at yield points. `parallel` treats a mid-dispatch unload as listener-absent, never a failure; serial/bail/waterfall skip dead listeners (waterfall: no veto). The emitter-side dispatch task stays untracked (C7).
- **Timeout budgets (S3)**: `Context::new_with_timeouts` injects a `TimeoutConfig` (all fields `None` by default — zero behavior change until a host opts in) bounding five waits: `apply` (body activation; Fail or bounded Retry), `listener` (per listener invocation in all five modes plus the `internal/config` chain), `drain` (per-consumer convergence wait in provider withdrawal; LogAndContinue or CancelConsumer), `cleanup` (per orphanable effect disposer; a timed-out disposer keeps running detached, never aborted), and `reap_watchdog` (reports a stuck tracked call each interval, never proceeds past a non-empty scope — teardown during an in-flight foreign call is UB). Abort-safe work times out by yield-point drop; tracked boundary work times out by stop-waiting while the call keeps running in the listener fiber's scope. The drain budget weakens the Thm 63 withdrawal wait by design, so the invariant layer's provider-residue arm is exempted exactly when a drain budget is configured.
- **Lifecycle guards (S4)**: `dispose` is single-winner idempotent — it sets the terminal `DriveState::disposed` flag *before* the atomic uid claim (order matters), so `request_epoch` refuses activatable epochs from that instant and no notify/restart race can re-activate a disposed fiber; losing callers join the winner's convergence and return once settled. `restart`/`update` on a disposed fiber fail with `fiber_disposed`; `update` during `Loading`/`Unloading` is rejected (`fiber_loading`/`fiber_unloading`); the Pending/Failed stash arm is preserved for pre-configuration.
- **Error classification + per-class policies (S5, D20)**: every `Error` carries a `class` (`Logic`/`Timeout`/`Transport`, constructor-set — `Error::new`/`msg` are `Logic`, boundary failures use `Error::transport` with explicit codes like `ffi_status`/`wasm_trap`/`plugin_load`/`payload_codec`). `ErrorPolicies` (via `Context::new_with_options`, defaults = pre-S5 behavior) grades per class: the log level of every kernel error line, an optional `RestartFiber`/`DisposeFiber` reaction on the *offending* fiber at every listener-failure settlement point (all five modes; propagation semantics untouched; the root fiber is never a target), and `ProviderQuarantine::DisposeOnTransportError` — a `Context::get` Invoker wrapper that disposes a provider fiber whose dynamic-channel calls fail transport-class. Automatic listener/transport *retries* are deliberately not offered (delivery counts are mode contract; no idempotency signal); the timeout class's retry knob is S3's apply retry. The dylib outbound detail JSON gained an additive `"class"` field; the WIT `kernel-error` variant set is unchanged.
- **Reactive resolution**: consumers declare `inject`; a fiber parks in `Pending` until all deps are available, then converges on the desired epoch (string of provider uids). Provider withdrawal drains consumers before the provider finishes unwinding: the provide-disposer removes the impl, notifies dependents, and joins every touched fiber (`service.rs`, `relied()` reverse index).
- **Deterministic update ordering (S6, D21)**: every dependency update of one reflect slot — provide/accessor apply arms and the withdrawal disposer prefix — runs `{mutation + notify}` (candidate recompute + refresh + `internal/service` emission) as one serial section keyed by `(label, name)` via `RootState::ordering` (`ordering.rs`); the consumer drain waits *outside* the section so a stuck consumer cannot block the group. Same-group updates are totally ordered and coherent (no torn state, no lost withdrawal event, event generation order == commit order); disjoint groups never block each other; the post-load batch notify needs no section (the slot's only writer is the owner fiber's driver). The five dispatch modes and the C5 no-order contract are unchanged — the guarantee covers *generation* order; listener-side observation order stays C5. Same-fiber convergence stays serialized by the driver loop (D4).
- **Sharded root state (P1)**: the hot `RootState` structures are striped (`crates/dougong/src/shard.rs`, 16 fixed stripes): reflect store by service name, dependency index per map key (service name / provider uid / consumer uid), fiber table by uid; the plugin registry and event store stay single-lock (cold path). Lock order: no root-state structure lock is held across another structure's lock or a fiber-internal lock — cross-structure flows snapshot, release, then act; an S6 group lock stays outermost. Dependency edges commit and uncommit under the uid captured at commit time (`Fiber::committed_uid`). External API is unchanged; contention benchmarks live in `crates/dougong/tests/bench_contention.rs` (ignored by default).
- **Runtime metrics (O2, D25)**: `Context::metrics()` returns a `MetricsSnapshot` (fiber state distribution, provider count, queue depth, drops, transition/notify/edge-wiring/retry counters, per-class error counts, and five latency summaries with fixed log2 buckets). Counters are always-on relaxed atomics on cold paths; latency instrumentation is construction-fixed opt-in (`ContextOptions.metrics`, default off = zero cost on the strict-resolution path). Exporters (Prometheus/OTel) are host wiring over the snapshot; the snapshot is not a consistent cut across concurrent transitions.
- **Structured logging (O1, D24)**: the kernel logs `LogRecord`s (field table: level/target/event/message/timestamp plus class/fiber/uid/realm/service/event_name/mode/from_state/to_state/cause/duration), not flat strings. `Logger::log_record` degrades to the flat `log` face by default, so pre-O1 sinks keep working and the plain-text needle surface is preserved; error lines grade their level through `ErrorPolicies::emit` (S5 stays single-sourced), lifecycle transitions log ungraded Info via `publish_transition` right before `internal/status`, and the quarantine record uses the provider realm's logger. No tracing dependency — the logger stays a replaceable service; a tracing bridge overrides one method.
- **Trace ids + boundary tags (O3, D26)**: `Fiber.trace` = the uid captured at construction, immutable — dispose retracts `uid` but never `trace`, so "start to fail to teardown" stays one joinable chain. Kernel `LogRecord`s carry `trace` plus the plugin form's `boundary` tag (`Plugin::boundary_tag()`: dylib host `"dylib"`, wasm host `"wasm"`, in-process `None`); transition records carry the exited state's span duration; `internal/status` payloads gain additive `"trace"`; `Context::trace_id()` is the public face. ABI vtable and WIT are unchanged — trace propagation inside cross-boundary payloads is O7 territory (caller identity needs an invoke-seam change).
- **System state events (O4, D27)**: the improve 三.4 event model lands entirely under `internal/`: fiber.created, fiber.<state> (real transitions only), provider.changed (fired at the `notify` funnel — one per name, ahead of `internal/service`, inheriting S6 commit ordering), effect.cleaned (finished disposers only), drain.started/finished (non-empty drains). `service.notified` and `event.dispatched` map onto the existing `internal/service`/`internal/dispatch` — no duplicate channels; `internal/status` stays as the snapshot event. Every payload is built by `events::system_event` (fiber/uid/trace/realm envelope + specifics). Observation order across event names stays C5.
- **Health snapshot (O5, D28)**: `Context::health()` returns `HealthSnapshot` — plugin/fiber counts, failed-fiber details, the recent-errors ring (cap 64, fed at the S5 emit funnel), long tasks (in-flight tracked boundary calls with their ages, via the S2 cancel-scope age registry), and stale providers (held slots whose provider fiber is not `Active`). `healthy` defaults to no-failed-and-no-stale; hosts override. HTTP endpoints are host wiring — the library only collects (`examples/health_demo.rs` composes the `/healthz` body).
- **Error categories + alerts (O6, D29)**: the improve 三.6 eight-group taxonomy is `ErrorCategory::of(class, code)` — a pure view, with `Other` for business errors. Per-category `CategoryAlert` rules (in `ErrorPolicies.alerts`) override severity, rate-limit log lines (the O5 ring still records), and emit one `alert` record per window at the threshold crossing. Empty rules = byte-identical default behavior.
- **Boundary-call tracing (O7, D30)**: `ContextOptions::boundary_trace` (default off) extends the S5 invoke-seam decorator (`BoundaryInvoke`) so every dynamic-channel call emits a `boundary_call` record with service/method/size/duration/outcome and the provider identity; the dylib require bridge records its outbound leg. Both sides record themselves and join on the O3 trace id — caller identity does not cross the boundary in payloads.
- **Plugin budgets (P7, D23)**: `BudgetConfig` (via `ContextOptions.budgets`, all-`None` default = zero change and zero atomic traffic) caps two kernel-metered resources per fiber: `max_effects` (live cleanup-bearing effects at the `register_effect` choke point — provides, accessors, listeners, bridges, teardowns; live-slot count, strict in-lock check, breach = `budget_exceeded` Logic error rolling back the activation or returning to the caller) and `max_event_emits` (plugin-facing emit admissions per activation window, reset at every body start; breach drops that emission, logs once per window through the policy table, reports `Dropped` from `emit_with_policy`). Kernel-protocol `emit_internal` is exempt so a budget cannot sever withdrawal propagation; compute metering stays a sandbox concern (wasm fuel/epoch/StoreLimits), since trusted dylib and in-process code has no enforcement point.
- **Lock-free active set (P4)**: `RootState::active` (`shard.rs::ActiveSet`) is a fixed atomic bitmap over dense monotonic uids (262,144 covered) plus a mutex-guarded tail beyond, so strict resolution (`fiber_is_active` on every strict get/check_impl) and per-transition flips take no lock. It is a mirror only — authoritative liveness lives in the fiber; correctness rides the store-stripe lock chain and the post-load republish-before-notify order, so semantics are identical to the pre-P4 mutex set and S1 deep checks still pin membership. B2 resolve storm ≈1.35× (`bench_contention`).
- **Bounded event dispatch (P2, D22)**: fire-and-forget `emit`/`emit_internal` enqueue listener invocations onto per-event ready lanes and a fixed worker pool (default 4) instead of per-listener `tokio::spawn`. Reliable synchronous emit stays lossless through the unbounded lane; `ContextOptions.events` (`EventQueueConfig`) configures bounded lanes, and `Context::emit_with_policy` provides async backpressure while `OverflowPolicy::Drop` is per-event opt-in. `queue_capacity` counts pending bounded listener invocations; per-event `max_concurrency` cannot head-of-line block other event names. Listener work still enters its fiber's `CancelScope` via `run`/`run_tracked`; parallel/serial/bail/waterfall and C5/C7 are unchanged. Benchmarks live in `crates/dougong/tests/bench_events.rs`.
- **Two-level capability check (TS Alg. 6)**: `Context::require` distinguishes `inactive_dependency` (declared but not committed) from `undeclared_dependency` (never declared). Boundary hosts must preserve this distinction when mapping to WIT `kernel-error`.
- **Dynamic channel (D6)**: cross-boundary services are `service-key{name, abi-hash} + method: u32 + bytes`, exposed through `dougong::Invoker`/`Invoke`. In-process typed keys (`Any` downcast) coexist; the kernel stores plain names.
- **Boundary adapters are isomorphic**: `dougong-dylib`'s `DynPlugin` and `dougong-wasm`'s `WasmPlugin` follow the identical ordering — register the teardown effect *first* (LIFO runs it last), then let the guest/exports provide; and both serialize every foreign call per instance (dylib's `InstanceLock`, wasm's store mutex) — consumer fibers call from their own tasks, so the kernel does not order those calls for you. Keep them in sync.
- **Event modes live at dispatch**: emit/parallel/serial/bail/waterfall are chosen by the dispatcher (`events.rs`), not at registration. `internal/*` events are framework extension points with scope filtering. In waterfall, a listener pulls `Next` to advance; dropping it vetoes the chain. Mode-aware bridges (`Context::on_dispatch`) receive the dispatch mode — boundary adapters use them, and `internal/*` names reject bridges.
- **Dylib events are CPS (D14, ABI v2)**: the descriptor's `listen` map registers bridges; in waterfall the plugin returns `STATUS_DEFERRED` from `on_event` (output = continuation payload, empty = original) and the host re-enters through `on_next` with the chain result. The v1 synchronous `NextFn` was removed — do not reintroduce sync continuations across the C boundary.
- **Isolation labels (D15)**: `Context::isolate(name)` mints a *fresh* label on every call; per-name overrides via `isolate_with_label` need a caller-held mapping (`dougong-loader`'s `scopes` map). Loader `isolate` rows are **realms** (`Context::isolate_realm`, D15): member provides land in the realm label, member injections prefer realm-local providers then fall back to the global default; realm services never leak to the default label.
- **WIT is the wasm contract's single source** (`wit/dougong-plugin.wit`, package `dougong:kernel@0.1.0`). Contract changes go through `dougong-design.md` D7's landing record.
- **Sandbox split (D5/D11)**: dylib = trusted, teardown-only (never `dlclose`; R1 accepted). wasm = untrusted: fuel per call + epoch yielding + `StoreLimits` + capability-empty WASI. The world import surface is the whole authority.

## Workspace discipline

- Lints are maximal (`pedantic + nursery + restriction` plus strict rust lints). The only allowed lints are documented-in-place: `cargo_common_metadata` (unpublished workspace), `multiple_crate_versions` (wasmtime/wit-bindgen pin different `syn` majors), and `significant_drop_tightening` on the wasm store guards (the guard deliberately spans the awaited export call — wasmtime serializes execution per store).
- Generated `bindgen!` output lives in `crates/dougong-wasm/src/lib.rs` under `mod bindings` with scoped allowances; do not hand-edit it.
- No `eprintln!`/`println!` in library or example code — log through `ctx.logger()`. No placeholder/`todo!` code; no `unwrap`.
- Comment only complex code, in American English; files compliant with the Rust guideline skill carry the `// Rust guideline compliant <date>` header.
- Wasmtime 48 API notes verified empirically (do not trust older memory): `instantiate_async` returns the wrapper directly (no tuple); component links need `wasmtime::component::Linker` + `add_to_linker::<T, HasSelf<T>>`; import trait signatures are flat WIT results (no `wasmtime::Result` wrapper); imported resources require implementing `Host::drop` with `ResourceTable::delete`; `WasiView::ctx` returns `WasiCtxView`.
- Long-running work is tracked under `.planning/` as named plans (e.g. `2026-10-20-dougong-impl`, `2026-10-21-full-code-review`), each with task_plan / findings / progress; pin a session with `PLAN_ID` when several run in parallel.
