# CLAUDE.md — dougong (kernel)

The composition kernel. Everything else in the workspace adapts to its semantics; read the root CLAUDE.md first.

## Invariants that span files (do not break)

- **Effect collection**: every environmental mutation goes through `Fiber::effect`; disposers unwind LIFO. `Context::provide`/`on`/`accessor` are thin wrappers over it — never mutate shared state outside this mechanism in a plugin-facing path.
- **ω before body**: the load path commits the committed view (store + provider candidates) *before* running the plugin body; the acceptance tests pin this (a provider can read its own service during activation; late consumers must not stay Pending).
- **Panic containment**: the plugin body runs on its own tokio task; a panic becomes a JoinError and maps to `fail_load`. The driver task must always survive.
- **Restart force**: `force = loaded != EPOCH_INACTIVE` — restarts of an inactive fiber must not trigger a spurious third activation.
- **`get`/`require` semantics** mirror TS Algorithm 6 (see root CLAUDE.md); the two error kinds are load-bearing for the boundary hosts' error mapping.
- **Drain ordering**: the provide-disposer removes the impl, notifies dependents, and joins every touched fiber, so consumers converge before the provider finishes unwinding (`service.rs`). The reverse-dependency index (`relied`) is O(1) and must stay consistent across commit/uncommit/dispose.
- **Invariant checkpoints (S1)**: every fiber lifecycle transition (spawn/load/unload/fail/dispose/driver landing) runs the matching `invariant.rs` checkpoint; a breach panics with a locating snapshot (a kernel bug, never a recoverable error). Release builds keep the O(1) field-relation tier; `debug_assertions` adds store/index/registry cross-consistency. Deep checks collect violations under the lock and breach after dropping it, and tolerate dispose-raced absence (present ⇒ must match exactly, absent ⇒ tolerated). New transitions must wire their checkpoint.
- **Cancel scopes (S2)**: every task a fiber owns spawns through `Fiber::task_scope` (`cancel.rs`), whose gate rejects spawns into a cancelled generation. `unload_once` and the load-rollback arms reap the scope *before* draining effects; `dispose` cancels up front (never reaps — it may be running on one of the fiber's own listener tasks). Bridges and wasm bodies are tracked-only; in-process futures abort at yield points. The invariant layer asserts `cancelled ⇒ task_count == 0` at post_unload/post_fail_load/post_dispose. The driver task itself and the emit dispatcher stay outside the scope (the driver is the reaper; C7 keeps emitter dispatch alive).
- **Lifecycle guards (S4)**: `DriveState::disposed` is the terminal flag; `dispose` sets it under the driver lock *before* the atomic `uid.take()` claim, and `request_epoch` then refuses any activatable epoch (the single choke point every refresh/notify/restart path funnels through). Exactly one dispose caller runs the teardown; losers join the convergence and return settled. `restart`/`update` guard disposal with `fiber_disposed`; `update` additionally rejects `Loading`/`Unloading` at entry (`fiber_loading`/`fiber_unloading`) — entry guards are point-in-time reads; mid-waterfall transitions are bounded by driver serialization plus the choke-point guard.
- **Error classes + policies (S5, D20)**: `Error.class` (`Logic`/`Timeout`/`Transport`) is constructor-set; `policy.rs` holds the construction-fixed `ErrorPolicies` table. Every kernel error log line routes through `ErrorPolicies::log`/`log_error` (never hardcode a level); every listener invocation that settles as a failure — in all five modes — runs `react_to_listener_failure` against the snapshot-captured offender fiber (weak; the root fiber uid 0 is never a target; the reaction runs detached). `Context::get` wraps `Invoker` reads in the quarantine decorator when `ProviderQuarantine::DisposeOnTransportError` is on. New error construction sites must pick an explicit class (`Error::transport` for boundary mechanics) instead of falling into the `internal` bucket.
- **Update ordering (S6, D21)**: `RootState::ordering` (`ordering.rs`) serializes dependency updates per `(label, name)` service group: provide/accessor apply arms and the withdrawal disposer prefixes run `{mutation + notify}` inside `UpdateSerializers::run`; the consumer drain stays outside the section. A group lock is always the outermost lock (sections never await and never re-enter — emission spawns tasks instead), so the lock order stays acyclic; disjoint groups never block each other. The post-load batch notify is exempt (the slot's only writer is the owner fiber's own driver). Any new same-slot mutation+notify path must run inside a section.
- **Sharded root state (P1)**: the hot `RootState` structures are striped (`shard.rs`, 16 fixed stripes): the reflect store by service name, the dependency index per map key (service name / provider uid / consumer uid), the fiber table by uid. Lock-order rule: no root-state structure lock (stripe or single) is ever held while acquiring another structure's lock or a fiber-internal lock — cross-structure flows snapshot under one lock, release, then act (the pre-P1 `notify` held the fiber table across `check_impl`, which deadlocked against checked services; that topology is gone and pinned by a `kernel_semantics` regression test). Edge updates lock one stripe at a time; the invariant layer's deep checks probe stripes one lock at a time and tolerate dispose-raced absence. Dependency edges are committed and uncommitted under the uid captured at commit time (`Fiber::committed_uid`), so a racing dispose cannot drift the cleanup key.
- **Timeout budgets (S3)**: `RootState::timeouts` (`TimeoutConfig`, construction-fixed, default all-`None`) bounds five waits — `apply` (body; rollback then Fail, or bounded Retry decided by the driver — never retry/park a stale target), `listener` (per invocation; plain = in-task drop, bridge = tracked spawn + await-side detach; `internal/config` resolves under it as a whole chain), `drain` (per-consumer join in the provide/accessor disposers; CancelConsumer cancels the stuck consumer's scope), `cleanup` (orphanable disposers run on detached tasks, timed-out ones keep running — never aborted; Critical kernel disposers are exempt), and `reap_watchdog` (logs `reap_blocked` per interval, never proceeds). Because the drain budget weakens the Thm 63 wait, the debug-tier residue checks exempt the `provider_consumers[self]` arm exactly when a drain budget is configured; a stuck consumer's stale edges self-clean on its later convergence or disposal.
- **Events**: five modes at dispatch time, threaded to `DispatchListener` bridges (`Context::on_dispatch`; `internal/*` names reject bridges); `internal/*` bypasses `internal/dispatch` recursion; `internal/update` may veto config updates (`Fiber::update`) — the accepted config is persisted only in the waterfall tail, so a veto leaves the previous config live.
- **Bounded event dispatch (P2, D22)**: `event_queue.rs` schedules emit/emit_internal listener invocations on per-event ready lanes with a fixed worker pool (default 4); a lane is ready only below its per-event cap, so hot events cannot head-of-line block other names. Reliable synchronous emit uses the lossless unbounded lane. `ContextOptions.events` configures bounded lanes; async `Context::emit_with_policy` waits under Backpressure, and only `OverflowPolicy::Drop` drops on a full lane. Queue jobs hold `Weak<RootState>`; execution uses `CancelScope::run`/`run_tracked`, preserving unload/reap and listener budgets. Parallel/serial/bail/waterfall do not use this queue.
- **Lock-free active set (P4)**: `RootState::active` (`shard.rs::ActiveSet`) is a fixed atomic bitmap over dense monotonic uids (262,144 covered) plus a mutex-guarded tail beyond; strict resolution (`fiber_is_active` sits on every strict get/check_impl) and per-transition flips take no lock. It is a mirror only — correctness rides the store-stripe lock chain and the post-load republish-before-notify order, so a transient stale read self-heals exactly as it did under the pre-P4 mutex; S1 deep checks still pin membership. The per-fiber driver mutex stays: it is uncontended by construction (one driver task; refresh arrivals only overlap the one-scheduler-hop dirty window), measured in findings §20.
- **Runtime metrics (O2, D25)**: `metrics.rs` hosts `Metrics` (on `RootState`), `MetricsConfig`, and the `MetricsSnapshot` face behind `Context::metrics()`. Counters are always on; latency sites gate on `Metrics::instant_if()` and record via `Metrics::record` — never time unconditionally on the resolution path. `dependency_rebuild_count` counts edge wiring events (non-empty `commit_edges` + `uncommit`), not provides; dispatch latency and the drop counter live on the P2 `Queue`, read through `EventDispatcher::queue_stats()`.
- **Structured logging (O1, D24)**: every kernel log line is a `LogRecord` written through `Logger::log_record` (default degrades to flat `log`, preserving the pre-O1 needle surface); `LogRecord::to_flat` is the single flat renderer. Error records grade through `ErrorPolicies::emit` only; transition records (`log_transition`, Info, ungraded) fire from `publish_transition(from)` where `from` is the mirror value `cache_state` returns — never add a lock acquisition inside `cache_state` itself. The quarantine record logs through the provider fiber's realm logger, like every other site.
- **Trace ids + boundary tags (O3, D26)**: every fiber carries `trace` — its uid as captured at construction, never retracted (dispose clears `uid` but not `trace`, so teardown records stay joinable to the lifecycle). Every kernel `LogRecord` of a fiber carries it plus the plugin form's boundary tag (`Plugin::boundary_tag()`, default `None`; DynPlugin returns `"dylib"`, WasmPlugin returns `"wasm"`); transition records carry the exited state's span duration (`state_since`/`last_state_ms`, driver-task private — `cache_state` captures on a real change, `log_transition` consumes). `internal/status` payloads gain additive `"trace"`; `Context::trace_id()` is the public binding face. No ABI/WIT change: propagating trace inside cross-boundary payloads needs caller identity at the invoke seam and belongs to O7's boundary-call record.
- **Plugin budgets (P7, D23)**: `RootState::budgets` (`budget.rs::BudgetConfig`, construction-fixed, default all-`None`) caps live effects (`register_effect` counts live slots, not `len` — disposed slots stay as `None` holes) and plugin-facing event emissions per activation window (`Fiber::emitted_events` + first-breach latch, reset in `load_once` before each body run). `admit_emit` is only called from `events::emit`/`emit_with_policy`; never gate `emit_internal` on it — kernel-protocol events must stay unbudgetable. An effect-cap breach during activation flows through the normal body-failure rollback; runtime breaches return to the registering call.
- **Parking_lot everywhere**: std Mutex poisoning is deliberately absent; do not reintroduce `std::sync::Mutex`.

## Where things live

`fiber.rs` is the core (driver loop, epochs, effects, drain); `context.rs` is the public surface; `service.rs` owns the reflect store + reverse index; `events.rs` the five modes; `event_queue.rs` the P2 bounded fire-and-forget scheduler; `registry.rs` spawns child fibers with the parent-cascade effect and the initial `check_impl` probe; `invariant.rs` hosts the transition checkpoints (fault-injection unit tests live in its `#[cfg(test)]` module); `policy.rs` hosts the S5 error-policy table, the listener-failure reaction, and the provider-quarantine decorator; `ordering.rs` hosts the S6 per-service-group update serializers; `shard.rs` hosts the P1 striped-map primitive behind the hot root-state structures. `budget.rs` hosts the P7 plugin-budget config; `logger.rs` hosts the O1 `LogRecord` face.

## Tests

`tests/kernel_semantics.rs` (behavior contract) and `tests/acceptance.rs` (paper §15 scenario mapping) are the regression net — any semantic change updates them, and any bug fix here should first reproduce as a failing case there. The stability tracks add one suite each: `cancel_scope.rs` (S2), `timeouts.rs` (S3), `lifecycle_guards.rs` (S4), `error_policy.rs` (S5), `ordering.rs` (S6), and `fault_injection.rs` (S7: repeated/concurrent hot updates, unload+inject+event races, dynamic realm fallback, panicking listeners pinned per dispatch mode). `tests/budgets.rs` covers P7 effect/emission caps, window reset, and the kernel-protocol exemption. `event_queue.rs` covers P2 worker bounds, per-event fairness, backpressure, drop, panic containment, and dequeue-time cancellation. Run with `cargo test -p dougong`. `tests/metrics.rs` covers O2: counter semantics, the latency gate, bucket invariants, and capacity drops. `tests/logging.rs` covers O1: the field table on error and transition records, the flat degradation, and the isolation-consistent quarantine record. The performance track keeps `bench_contention.rs` (P1), `bench_events.rs` (P2), and `bench_notify.rs` (P3: notify convergence-cost counters over same-target refresh churn, multi-service withdrawal fan-out, and chain propagation; the `internal/status`/`internal/service` counts are the anchored metrics — `service_events` must stay byte-identical across runs): `#[ignore]`d benchmarks with recorded baselines, run with `cargo test --release -p dougong --test bench_contention -- --ignored --nocapture`, `--test bench_events`, or `--test bench_notify`.
